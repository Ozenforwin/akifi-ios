# Akifi iOS

Native iOS personal-finance app (SwiftUI, Swift 6) on a Supabase backend
(Postgres + Auth + Storage + Edge Functions) with Firebase (Analytics,
Crashlytics, FCM, Performance). `README.md` is the accurate architecture
document — read it first; this file is the short operating manual.

## Repository layout

```
AkifiIOS/            app sources (Models, Repositories, Services, ViewModels, Views, Localization, Shared/Widget)
AkifiWidget/         WidgetKit extension
AkifiIOSTests/       XCTest suite (600+ cases)
AkifiIOS.xcodeproj   generated by XcodeGen from project.yml, committed
project.yml          XcodeGen spec — the source of truth for targets, versions, packages
supabase/
  migrations/        SQL migrations (never edit one that is already applied)
  functions/         Deno edge functions; _shared/ holds paging, FX, auth, schedule helpers
  tests/             *.assert.sql dry-run assertions (NOT migrations — never put them in migrations/)
Scripts/             CI lints and their fixture tests
Config/              xcconfig template (Debug/Release.xcconfig are generated, gitignored)
codemagic.yaml       CI/CD: ios-release (push to main) and ios-submit-review (tag release/v*)
release-notes/       hand-written What's New per version (<version>.json)
.claude/adr/         ADR-001 multi-currency, ADR-002 tool-calling agent, ADR-003 complete-set reads
.claude/research/    release-process.md
```

There is no PHP/Laravel backend, web app or Android app in this repository.

## Tech stack

- Swift 6 (strict concurrency), SwiftUI, iOS 18+, `@Observable` view models, Repository + DataStore pattern
- supabase-swift 2.43, Firebase 11.15, GoogleSignIn 8 — pinned in the committed `Package.resolved`
  (`AkifiIOS.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/`); CI builds with
  `-onlyUsePackageVersionsFromResolvedFile`
- XcodeGen (project.yml), Codemagic (CI), Deno (edge functions)
- Three languages: ru (source), en, es — all in `AkifiIOS/Localization/Localizable.xcstrings`

## Commands

```bash
xcodegen generate                      # after editing project.yml (needs Config/Debug.xcconfig + Release.xcconfig; copy Config/Config.xcconfig.template)

# Swift tests (use your own derived data and a simulator id from `xcrun simctl list devices available`)
xcodebuild test -project AkifiIOS.xcodeproj -scheme AkifiIOS \
  -destination 'id=<SIMULATOR-ID>' -derivedDataPath .dd -quiet
xcodebuild test ... -only-testing:AkifiIOSTests/<Suite>      # one suite

# Edge function tests — run from each directory that has *.test.ts
(cd supabase/functions/_shared && deno test --allow-env)
(cd supabase/functions/assistant-query && deno test --allow-env)

# CI lints — all three are blocking in codemagic.yaml; run them before every commit
bash Scripts/lint-amount-usage.sh --strict          # ADR-001
python3 Scripts/lint-unbounded-fetch.py --strict    # ADR-003 (Swift and supabase/functions/**/*.ts)
bash Scripts/lint-date-formatters.sh --strict       # every DateFormatter via AppDateFormatters
python3 Scripts/test-lints.py                       # fixture tests: the lints must still catch their bad examples
```

There is no `swift test`, `php artisan`, `npm` or `gradlew` here. Never report
"tests pass" unless `xcodebuild test` (and `deno test` for server changes)
actually ran and was green.

### Database changes

- New schema change = new file in `supabase/migrations/` (timestamped). Never edit an applied one.
- Apply with a SQL POST, **not `supabase db push`**: the Supabase Management API
  `POST https://api.supabase.com/v1/projects/fnvwfrkixjqdifitlifr/database/query`
  (`{"query": "...", "read_only": false}`, `Authorization: Bearer <CLI token from the macOS keychain>`),
  then record the version in `supabase_migrations.schema_migrations`. The CLI hangs
  when `SUPABASE_ACCESS_TOKEN` is exported empty. Never print the token.
- Dry-run first: `begin; <migration>; <assertions raising 'ASSERT FAILED'>; rollback;`.
  Keep assertions in `supabase/tests/*.assert.sql`.
- Edge functions called by cron need `verify_jwt = false` in `supabase/config.toml` **and**
  `supabase functions deploy <name> --no-verify-jwt --project-ref fnvwfrkixjqdifitlifr`.

## Conventions

- Code and comments in English; user-facing strings in the xcstrings catalog with ru, en and es
  values (never ship a key without all three).
- Git: Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`); PR for merges to main.
- Money: `amount_native` is in the ACCOUNT's currency; never sum or convert the legacy
  `amount`/`currency` label (ADR-001). Dates go through `AppDateFormatters` (en_US_POSIX + gregorian).
- Architecture is MVVM + Repository + DataStore with dependency injection through the SwiftUI
  environment; business rules live in `Services/` (pure, testable), not in Views.
- Add an XCTest for every logic change (pure functions / view models).
- Never commit secrets, `.env` files, API keys or xcconfig files with credentials.
- Never modify a migration that is already deployed.

## Deployment

- iOS: Codemagic. Push to `main` -> `ios-release` (lints, Deno tests, unit tests, IPA, TestFlight).
  Tag `release/vX.Y.Z` on the commit that was built -> `ios-submit-review`
  (selects the build made from that very commit, writes What's New, submits for review).
- Backend: Supabase (project ref `fnvwfrkixjqdifitlifr`); edge functions deployed by hand with the CLI.
- Toolchain is pinned (Xcode, XcodeGen, Deno, pip packages, Package.resolved): change a pin deliberately.

## iOS release rule — never push a closed train

Before pushing iOS changes that may trigger TestFlight upload, sanity-check that `MARKETING_VERSION` in `project.yml` is NOT a version that's already approved or in review on App Store Connect. The `ios-release` workflow has a pre-flight guard that aborts on a closed train, but a stale `project.yml` still wastes 5 minutes of CI minutes before the guard fires.

Rule of thumb: after any successful App Store submission, the FIRST commit to `main` should bump `MARKETING_VERSION` (1.3.0 → 1.3.1). The auto-bumper in `codemagic.yaml` will then march forward from there.

Full release walk-through (push triggers, tag triggers, what to do when something fails): `.claude/research/release-process.md`. Skill `codemagic-ios-cicd` (lessons 13-15) covers the fix history.

## Data-layer rule — complete-set reads (ADR-003)

PostgREST silently truncates responses at `max-rows`. **Every list read from
Supabase goes through `SupabasePaging.all(...)`** — never a bare
`.select()…execute().value` into an array. The helper pages until the server's
own count is satisfied, enforces a primary-key tiebreak and self-checks the
result; no client constant may decide whether the user sees all their rows.
Edge functions use `fetchAll` / `fetchAllIn` from `supabase/functions/_shared/paging.ts`.
`python3 Scripts/lint-unbounded-fetch.py --strict` (Swift and edge-function TS) runs in CI and fails on
violations; a genuinely bounded read needs `// bounded-fetch: <reason>`.
Never justify an unpaginated read with "the table is small" — that is how
the 2026-09-10 shared-balance incident happened. See `.claude/adr/ADR-003-complete-set-reads.md`.

## Self-testing rule — data-layer bugs

Whenever a fix concerns what the user sees (balances, analytics, AI answers,
budget numbers, transaction amounts), **verify the real data in Supabase
before reporting "fixed"**. Unit tests run against fixtures; fixtures can't
catch legacy rows written by a previous client / TMA / broken write-path.

Mandatory check flow:
1. `supabase db query --linked --output table "SELECT ... FROM transactions WHERE ..."`
   to see the actual row (`amount`, `amount_native`, `currency`, `foreign_*`,
   `fx_rate`, `account_id`) — not just what the Swift model computes from it.
2. JOIN against `accounts` to verify `t.currency == a.currency` and
   `amount_native` is in that currency's minor units. A mismatch means a
   legacy row that the Swift read-path can't rescue — needs SQL reconciliation.
3. When in doubt, run an UPDATE against a snapshot in `backup_YYYYMMDD` schema
   first, then the production rows.

Tooling available in this environment:
- `supabase db query --linked` — direct SQL to the linked project (prod).
- `xcodebuild test -scheme AkifiIOS -only-testing:AkifiIOSTests/<Suite>` — Swift tests.
- `xcodebuild build` — iOS compile.
- `xcrun simctl` — simulator automation for UI smoke tests.
- `bash Scripts/lint-amount-usage.sh` — ADR-001 guardrail.
- `deno test --allow-env` (per function directory) — edge function tests.
- `supabase functions deploy <name> --project-ref fnvwfrkixjqdifitlifr` — edge functions.
- Claude-in-Chrome MCP — browser automation for web UI.

Do NOT report a bug as fixed without at least one of these verifications
against the real data path. Saying "tests pass" while the user's screen
still shows the bug is worse than saying "tests pass, but I can't verify
against your data — please check".
